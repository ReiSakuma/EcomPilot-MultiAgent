# v65 面试核心精简说明

## 目标

v65 的目标不是继续叠加补丁，而是让主链路具有更少的模型责任、更小的结构化协议和清晰的失败边界。面试时应能在几分钟内说明每个节点为何存在，以及模型和程序各自拥有什么决策权。

## 保留能力

1. 自然语言请求编译、错别字容错、缺失字段澄清和多意图路由。
2. 前置业务与安全校验，非法数字、毛利冲突和未确认宣传不进入昂贵主链路。
3. 市场样本分层、异常值清洗和心理售价门控。
4. Listing 内容生成与确认事实白名单。
5. Strategy 单方案生成和最多一个可选只读证据工具。
6. 本地工具拥有优惠上限、毛利率、库存等业务数字。
7. 确定性 Review 加一次可选语义审核。
8. 用户审批、幂等写入、回读校验和未知写状态保护。
9. 会话任务、checkpoint、长期记忆、租户权限、Trace 和只读运维页。
10. 独立 Analytics 路由，用于追溯已上架商品的销售表现。

## 删除能力

- Strategy 的 2 到 4 个动态候选方案池。
- 候选模拟、候选评估、模型重选和确定性候选收尾。
- EvidencePlan、EvidenceLedger 和独立调用预算账本。
- Review 遇到截断后的 4096 token 紧凑重试。
- 商品上新服务对 Market/Analytics ReAct 的强制要求。
- UI 中的候选提案、候选裁决和四次逻辑调用预算面板。

这些能力并非永远无价值，而是在当前单品上新演示中收益低于复杂度成本。需要 A/B 多策略实验时，应作为独立的“策略实验”用例重新加入，而不是塞回默认上新链路。

## 协议边界

### Strategy 模型输出

模型只输出 `launch_plan`、`rationale` 和 `discount_amount_yuan`。程序随后计算并覆盖售价和优惠上限、到手价和毛利率、计划投入和库存余量，以及最终可执行文案中的全部数字。

模型建议超过安全上限时会被裁剪并写入 `proposal_audit` 与 `semantic_corrections`。

### Review 模型输出

模型只输出最多三条语义问题：问题类型、字段路径、字段原文和短消息。无法在指定字段中找到原文的问题会被丢弃。数字一致性、库存和毛利不交给 Review 模型。

Review 模型调用失败或输出无效时，记录 degradation 后继续确定性审核，不再进行模型补写。确定性审核失败仍会阻止执行。

## 调用上限

- 请求编译：通常一次，结构化修复最多一次。
- Listing：一次生成，格式错误时最多一次结构化修复。
- Strategy：一次直接输出，或 ReAct 的“选择工具 + 最终输出”两次模型交互；最多一个证据工具。
- Review：一次 900 token 语义检查，无模型重试。
- Browser：无模型调用，仅在用户审批后使用确定性工具写入和回读。

## 验收标准

1. 正常上新在未审批时到达 `waiting_for_approval`，不修改店铺。
2. 审批后幂等执行并通过回读校验。
3. Strategy 结果不存在候选协议字段，证据工具数量不超过一个。
4. Review 输出截断或不可解析时不拖垮已通过确定性安全审核的任务。
5. DeepSeek 普通结构化请求关闭 thinking，避免推理内容挤占 JSON 输出预算。
6. 运维端只读，用户端模型调用数与 Trace 使用同一任务记录。
