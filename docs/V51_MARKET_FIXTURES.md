# EcomPilot MultiAgent v51 市场样本技术文档

## 1. 版本目标

v51 不实现异常价格清洗，而是先建立一套能验证清洗算法的数据。没有故意加入的边界样本，后续算法即使写错，也可能在普通数据上看起来正确。

## 2. 数据构成

无线耳机和机械键盘各包含 100 个商品、200 条评论：

| 类型 | 每类数量 | 例子 | 后续预期处理 |
| --- | ---: | --- | --- |
| 常规商品 | 94 | 主流新品 | 进入正常统计候选 |
| 极端但合理 | 4 | 清仓、官方翻新、高端旗舰、客制化 | 保留证据，按价格层分类 |
| 明显脏数据 | 2 | 配件错分类、分/元导入错误 | v52 识别并逻辑排除 |

无线耳机特殊样本为 `earbud_095` 至 `earbud_100`，机械键盘为 `keyboard_095` 至 `keyboard_100`。

## 3. 为什么要同时放入四种边界样本

- **超低但合理**：清仓和翻新商品是真实存在的，不能仅因价格低就删除，但不能冒充常规新品价格。
- **超高但合理**：高端品牌、额外材质、服务和客制化能够解释高价，应该保留在全市场或相邻档次证据中。
- **超低脏数据**：耳塞套、拔键器等配件被错放进整机类目，会错误拉低均价。
- **超高脏数据**：把“分”当成“元”等导入错误，会严重拉高均价。

这使后续系统必须区分“统计上极端”和“业务上不可信”，不能见到离群值就一律删除。

## 4. 离线标签与生产隔离

生成文件中的特殊样本带有：

- `test_case`：常规、脏数据或合理极端。
- `expected_statistical_flag`：统计方法是否应将其标成边界候选。
- `expected_excluded`：最终是否应从核心统计中排除。
- `expected_market_layer`：后续应进入哪个市场证据层。

这些字段相当于测试答案。`app/tools/market_data.py` 在生产加载时会将它们剥离，Agent 只能看到商品事实和解释字段，不能偷看预期结果。

## 5. 生成结果

| 品类 | 最低价 | 最高价 | 原始均价 | 中位价 |
| --- | ---: | ---: | ---: | ---: |
| 无线耳机 | 9.9 | 9999 | 294.809 | 189 |
| 机械键盘 | 8.8 | 12999 | 463.198 | 329 |

原始均价明显被脏数据抬高，而中位价相对稳定，这正是 v52 要使用稳健统计方法的原因。完整报告在 `reports/v51/market_fixture_distribution.json`。

## 6. 运行时与 SQL 变更

- SQL 数据集版本从 `tenant-market-v3` 升级为 `tenant-market-v4`。
- 发现旧版本 SQLite 时自动从 JSON 安全重建。
- Listing Agent 的竞品上下文只保留 ID、标题、价格、销量、功能和受众等必要字段；完整证据仍保留在 Market Artifact 中。
- v51 使用独立的会话、Checkpoint、分布式运行时数据库和安全账本文件，避免污染 v50。

## 7. 测试

`tests/test_v51_market_fixture_quality.py` 验证：

1. 两类数据各为 100 个商品和 200 条评论，ID 唯一。
2. 94/2/4 构成正确。
3. 六个特殊样本真实改变价格分布，并会被 log-MAD 或 IQR 标记。
4. 合理极端样本保留，脏数据具有排除期望。
5. 运行时不会泄漏离线测试答案。
6. `tenant-market-v3` 会重建为 v4，两个品类各有 100 行。
7. 扩展样本元数据不会挤掉 Listing Agent 的商家记忆。

## 8. 版本边界

v51 的页面和旧市场报告仍展示原始最小值、最大值和中位价，因此价格带可能出现 9.9 至 9999 元这样的范围。这是刻意保留的验收输入。v52 才会实现确定性异常检测与审计，v53 再实现核心、相邻和全市场三层可比证据。
