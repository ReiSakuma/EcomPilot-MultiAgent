# V35 Bad Case 复盘

## SQL 结构不合规

早期 Market Agent 可能一次输出多条 SQL 或未使用允许字段。处理方式是 SQL AST 白名单、租户条件注入、
只读连接和受控规范化；危险 SQL 失败关闭，不能因为“自动修复”而扩大查询权限。

## Strategy 或 Listing 出现无依据表述

这类错误不再立即杀死整个任务。系统把确定性事实和可修订文案分开，只清理无证据的宣传内容，记录修正审计，
在有限次数内复审；价格、库存和毛利不允许由修订模型随意改写。

## Review 输出过长或结构损坏

先限制上下文和输出预算，再做一次受控 JSON 修复，最后通过 Pydantic 校验。修复失败会返回统一 FailureEnvelope，
不会把半结构化文本当成可执行计划。

## 重复提交和并发点击

同一租户的 `client_request_id` 是幂等键。相同内容只创建一个 Turn，不同内容复用同一键则明确冲突；
SQLite `BEGIN IMMEDIATE` 保证本地 MVP 中并发提交只有一个创建者。

## 商品名称误解析

宽泛别名曾让“Alpha 游戏耳机”同时命中所有游戏耳机。v35 改为精确别名优先，宽泛结果只作为候选；
存在多个候选时必须让用户选择，静默误选目标为 0。

## 外部服务失败

离线门禁不掩盖外部服务状态。DeepSeek 超时、额度不足和 Playwright 不可用分别显示为技术故障；
测试桩调用与真实调用分开计数。生产级熔断、死信队列和跨实例恢复属于 v36 之后范围。
