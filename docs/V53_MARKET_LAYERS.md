# EcomPilot MultiAgent v53 三层可比市场证据

## 1. 本版解决什么问题

v52 能判断价格记录是否可信，但“真实商品”不等于“适合拿来和当前商品比较”。例如，699 元高端耳机和 49 元清仓耳机都可能是真实记录，却不应共同抬高或压低普通游戏耳机的参考价。

v53 在异常清洗之后增加可比性分层：

1. `core_comparable`（核心可比层）：和目标商品在品类、形态、功能、人群、渠道、成色及品牌档次上足够接近，用于计算参考价、常见卖点和用户痛点。
2. `adjacent_tier`（相邻档次层）：真实但不同档次或不同交易背景的商品，例如高端品牌、清仓、翻新、组合装或不同形态，只用于解释市场层次。
3. `full_valid_market`（全量有效层）：v52 排除脏数据后剩余的整个品类市场，用于展示全局范围和审计，不能直接否决用户定价。

## 2. 为什么目标售价不能参与选样

如果系统先看到用户想卖 699 元，再专门挑高价商品证明 699 元合理，结论就会被答案反向污染。v53 的 `ComparableMarketInput` 因此故意没有 `target_price` 字段，额外字段也会被 Pydantic 拒绝。

Market Agent 只把以下可信事实交给分层器：

- 规范商品类目；
- 已确认的商品形态与功能；
- 目标人群；
- 渠道、成色和品牌档次。

用户把目标价从 199 元改成 699 元，只要以上事实不变，核心样本 ID 和证据哈希就必须完全一致。

## 3. 分层与参考价如何产生

系统先由 v52 的确定性清洗器排除单位错误、非法价格、重复 SKU 和明显脏记录，再由 `classify_market_layers()` 逐条判断可比性。每条记录保存匹配维度、不匹配原因、功能重合率、相邻组别和最终层级。

核心层不少于 5 条且分布稳定时，使用清洗后均值作为 `core_reference_price`。均值和中位价差异超过 5% 时回退中位价；样本不足或疑似多峰时降级为 `advisory_only`，只给建议，不形成后续硬门控。

评论不会跨层混用。核心层评论生成当前商品的高频卖点和痛点，相邻档次评论只留作相邻市场解释，全量评论用于审计。

## 4. 协议与集成

- `ComparableMarketInput`：分层所需的可信输入协议。
- `MarketLayerDecision`：单个商品为什么进入某层的审计记录。
- `MarketLayerEvidence`：某层的商品、评论、数量和价格分布。
- `ComparableMarketEvidence`：三层证据、参考价、告警及 SHA-256 内容哈希。
- `ResearchEvidence`：Market Agent 的正式 Artifact，保存三层证据供 Listing、Strategy、Trace 和 Run Bundle 使用。

上下文管理器只向后续 Agent 投影核心参考价、参考方法和全市场范围，不把 98 条逐条裁决都塞进模型上下文。完整审计仍保存在 Artifact 和 Run Bundle 中。

## 5. 当前样本验收口径

| 品类 | 原始 | 有效 | 核心 | 相邻 | 核心价格带 | 全量有效价格带 |
| --- | ---: | ---: | ---: | ---: | --- | --- |
| 无线耳机 | 100 | 98 | 94 | 4 | 129-239 元 | 49-899 元 |
| 机械键盘 | 100 | 98 | 94 | 4 | 159-499 元 | 39-1299 元 |

带“游戏爱好者 + 已确认功能”的普通无线耳机输入会把清仓样本放入 `entry_or_clearance`，把高端样本放入 `premium_or_luxury`。合理极端商品若与输入确实同层仍可进入核心组；若因此导致样本少或分布不稳，系统只给建议。

## 6. 验证方式

```bash
cd /home/theburningmuses/EcomPilot_MultiAgent/v53
python scripts/run_v53_acceptance.py
pytest -q tests/test_v53_market_layers.py
pytest -q
```

机器可读报告写入 `reports/v53/v53_acceptance.json`，其中包含三层样本、评论归属、价格分布、逐条理由、内容哈希及 199/699 元目标价独立性证明。

当前验收结果：v53 定向测试 9 项通过，高相关兼容测试 50 项通过，完整回归 491 项通过。

## 7. 本版边界

v53 只负责建立可信、可比、可复算的市场证据，不负责判断用户目标价是否偏离市场，也不暂停工作流。价格阈值、用户确认和 Checkpoint 恢复属于 v54。
