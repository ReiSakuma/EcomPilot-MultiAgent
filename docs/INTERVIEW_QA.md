# Interview Q&A

## 为什么不用 ChatGPT 直接做

ChatGPT 可以生成标题和策略建议，但不能稳定承担毛利计算、库存判断、权限审批、幂等
写入、失败恢复和页面状态核验。本项目让 LLM 做生成，让确定性模块守业务边界。

## 为什么不是单 Agent

拆分依据是 Context、工具权限和失败边界，而不是模拟组织架构。Browser 是唯一有写权限
的 Agent；Strategy 才能使用财务工具；Review 汇总两个并行分支并执行硬约束。

## 为什么也不是纯固定 Workflow

流程拓扑固定，但 Listing、策略表达和审核说明需要针对市场证据与目标人群生成。完全
固定规则难以覆盖语言变化；完全自由 Agent 又难以保证副作用安全，所以采用混合架构。

## 和 LangGraph 有什么区别

概念上都有 State、Node、Edge 和 Checkpoint。当前 Runtime 更小、行为透明、针对单一
工作流；LangGraph 在动态图、生态集成和成熟持久化方面更强。当前不迁移是范围取舍，
不是认为自研框架普遍优于 LangGraph。

## 为什么计算不用 LLM

毛利和库存有明确公式、边界与可重复预期。让概率模型计算会增加精度风险且难以回归。
LLM 可以解释工具结果，但不能改写结果。

## 为什么 Browser 不自由点击

上架和优惠券是有副作用操作。自由点击会扩大动作空间和恢复歧义。固定 ExecutionPlan、
稳定 selector、一次性 Ticket 和字段回读更容易授权、审计与复现。

## 为什么 200 OK 不算完成

请求可能只被接收，页面字段可能未落库、被覆盖或部分成功。完成定义是观察到的商品与
执行计划逐字段一致，而不是 HTTP 层成功。

## 默认 model_call_count 为什么是 0

默认回归关闭 LLM Agent，保证快、便宜、稳定。只有显式配置 Provider 和 Agent 后才有
真实模型调用。最终报告不会把 deterministic 数据填进 Real LLM 列。

## Memory 做到什么程度

只检索人工种子的品牌语气、禁用表达和品类经验，并过滤 inactive 记录。它是 Context
辅助，不是向量 RAG，也不会自动把 Reflection 写成长时记忆。

## 最大不足是什么

Seller Center 是自建模拟后台，市场数据是本地快照，状态存储适合单机。真实平台会新增
登录、MFA、验证码、selector drift、平台条款和分布式一致性问题。

## 如何证明模块不是堆砌

用三个消融回答：Schema 降低结构失败，确定性 Review 防止硬约束漏过，Read-back 发现
提交成功后的状态漂移。固定故障注入和真实模型实验必须分开解释。
